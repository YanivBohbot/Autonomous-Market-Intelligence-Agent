# memory-workflow

**Type:** Supporting (standing project rule — NOT a superpowers skill)
**Source:** Your own instruction, captured in `feedback_workflow.md`

## What it is
Checkpoint frequently: save to file-based memory + git push at each step, so work is never
lost. Convert relative dates to absolute; one fact per memory file; index in `MEMORY.md`.

## Why it's here
Not a superpowers skill, but it governed how every other skill's output was preserved —
it's the reason the project has a continuous, recoverable history across sessions.

## How we used it on this project
20+ memory entries indexed in `MEMORY.md` track every phase: deployment design, security
review, cost estimate, Phase 6a/6b/7, durable checkpointer, SES email, the 2026-05-25
session wrap. Related lessons captured the same way: `test_before_push`,
`smoke_vs_grounded_qa`, `secret_redaction`.
